# Few-shot Usage Policy

Purpose: use historical-style cases to stabilize judgment without copying a previous answer mechanically.

## Rules

1. Match **task structure**, not topic keywords. A wind-tunnel example can teach proposal closure for another field; a kinetic-equation review can teach JCP evidence standards for a different numerical method.
2. Extract only the transferable pattern: bottleneck, decision rule, evidence requirement, output form.
3. Do not import old numerical targets, names, budgets, journals, or deliverables unless the current task supplies or explicitly reuses them.
4. If a current template or call conflicts with an example, the current constraint wins.
5. Use examples to choose the **depth and order of reasoning**, not to fabricate evidence.
6. Keep diagnosis distinct from rewrite. When the structure is weak, identify the highest-impact structural defect before polishing text.
7. For reviewer tasks, never reproduce a historical recommendation automatically. Re-evaluate the current manuscript and stage.
8. For new research ideas, examples should help identify a necessity gap and decisive experiment; they are not proof that novelty exists today.

## Example format

Each example contains:
- **Trigger** — representative user request;
- **Mode** — which top-level skill/mode should handle it;
- **Key judgment** — what must be decided;
- **Pattern to reuse** — transferable reasoning rule;
- **Ideal response shape** — the preferred output architecture;
- **Failure to avoid** — common but weak response pattern.
